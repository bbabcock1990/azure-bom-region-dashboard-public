👋 Getting Started

Run this dashboard against a customer's Azure subscription to see available SKUs, BOM coverage, quota headroom, and recommended regions — all in one place.

  1. 1

    Pick or create a BOM

    Bills of Materials live in the Bills of Materials list on the left. Click one to load it (and its latest analysis), or click + New to create one. The selected BOM — its name, customer, subscription, and controls — appears in the panel at the top of this area.

    Behind the scenes, your one-time browser sign-in mints an ARM bearer token. The dashboard then uses Azure's public management APIs directly for both service and VM SKU availability.

    • ARM Microsoft.Compute/skus — region- and zone-level VM SKU availability for the selected subscription. This is where region-wide and zonal NotAvailableForSubscription restrictions come from.

    ARM only accepts a token issued for the subscription's home tenant, so the dashboard automatically resolves the subscription tenant and requests the right token before a run.

    • Have Reader on the customer subscription, or
    • Ask the customer to run this dashboard themselves in their tenant — same workflow, their browser sign-in.
  2. 2

    Create the customer's BOM (in the dashboard)

    Each customer needs a Bill of Materials describing the Azure services they consume plus the SKU families and required cores per workload. Click + New in the Bills of Materials list (left), or Edit an existing BOM from its panel.

    • BOM Name — a short, memorable label (e.g. Contoso-Prod) that shows up in the BOM list so it's easy to tell BOMs apart.
    • Services — pick from the built-in Azure service catalog. The dashboard calls ARM providers/{ns}?api-version=2024-07-01 live to compute the per-region ✅/❌ matrix — no need for a CLI run.
    • Required SKUs — one row per SKU family. Family ID is the bit Azure quotas use (e.g. standardDav6Family), and the required-cores field drives the Quota Status column on the dashboard.

    Already have a bom_template.xlsx or region_results_*.xlsx from the legacy CLI flow? Click Import xlsx in the BOM editor to prefill the form.

  3. 3

    Run the analysis

    Select your BOM in the left list, then click ▶ Refresh analysis in its panel. Once a BOM is saved the run dialog defaults to Use saved BOM — pick a segment, confirm the BOM name, and hit Refresh analysis. A live progress bar streams ARM SKU availability status across all ~38 Azure regions — it usually takes a few minutes for the full set. (You can still drop a region_results_*.xlsx in to use the legacy xlsx path.)

  4. 4

    Explore the results

    Switch tabs to dig into different facets of the analysis result:

    • Overview — donut KPIs for Health, BOM coverage, SKU coverage, tier mix
    • Table — per-region detail with sortable columns
    • Map — geographic view of healthy vs. unhealthy regions
    • Latency Chart — round-trip latency from a chosen source region
    • Compare — side-by-side 3-region drill-down
    • Quota per Region — legacy quota view for older snapshots
    • Settings → Activity Log — audit trail of API calls, quota requests, BOM changes, and sign-in activity

Past analysis results are stored locally and reachable from the Analysis Result picker in the selected BOM's panel — switch between results without re-running the pipeline.

Sign-in

⏳ Checking sign-in…
How does this work?
  1. Click Sign in — a browser window opens once for your Microsoft sign-in. The local backend then mints an ARM bearer token in-process (no Azure CLI required).
  2. Your sign-in is cached, so later runs are silent until Azure asks you to refresh.
  3. Sign out clears the cache. Switch directory signs out then immediately re-opens the sign-in prompt so you can pick a different account or tenant.
