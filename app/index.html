Settings

Manage your default support contact, the model's reference data, and the activity log.

Ticket owner

The Azure support contact used as defaults on every ticket created from this dashboard. Azure requires a contact name, email, and country.

Permissions

Checks whether the signed-in account has the Azure permissions the dashboard needs on a subscription. Required capabilities power the core analysis (region readiness, quota, SKU & zonal availability); optional ones unlock automation like deployment pre-flight, quota-increase requests, and support tickets. This is a read-only check — it lists your own effective permissions and matches them locally; it changes nothing.

Pick a subscription and choose Check permissions to run the access check.

Model datasets

The reference data the analysis is built on — the region latency matrix, region & service catalogs, and the default region / SKU seed lists. These stay current automatically: pull the region catalog and SKU families live from your Azure subscription with Refresh from Azure, or point a dataset at a file URL (e.g. a GitHub raw link) and Refresh from URL. Every refresh is validated, takes effect immediately, and never overwrites the built-in copy — use Revert to restore it. Download exports the current file.

Cost & pricing

Controls the BOM cost estimate. Compute cost is pulled live from the public Azure Retail Prices API (per-vCPU list price × required cores). Non-compute cost is estimated as a percentage uplift on compute plus any per-service figures you enter below.

⚠️ All cost figures are estimates only — list prices anchored to a representative VM size, not a quote. Actual cost depends on real VM sizes, run hours, storage, egress, licensing, and your negotiated agreement.

Per-service monthly estimates (optional)

👋 Getting Started

This dashboard shows a customer where their Bill of Materials can deploy — available SKUs, quota headroom, best regions, and blockers you can turn into an Azure support ticket. Here's the whole flow in five short steps.

Sign-in

⏳ Checking sign-in…
How does this work?
  1. Click Sign in — a browser window opens once for your Microsoft sign-in. The local backend then mints an ARM bearer token in-process (no Azure CLI required).
  2. Your sign-in is cached, so later runs are silent until Azure asks you to refresh.
  3. Sign out clears the cache. Switch directory signs out then immediately re-opens the sign-in prompt so you can pick a different account or tenant.

How this workload is deployed. Zone-redundant spreads services across Availability Zones for HA, so a tier that's restricted from zone redundancy in a region is a hard blocker (region goes red). Regional tolerates a single zone, so zone-redundancy restrictions are advisory only and won't block a region.

The origin this customer measures inter-region latency from — e.g. their primary Azure region or where their users are. Saved with the BOM and used as the default Source region on the Latency tab and in the "Best regions" latency badges. Latency values come from Microsoft's published Azure region round-trip matrix.
